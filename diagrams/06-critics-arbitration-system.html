Spec Authoring Phase — Before the Lark Parser
The Spec Closure System validates specs during the AUTHORING phase — before the Lark parser. It activates when an LLM generates or refines a .dmx spec from natural language. When a SWE writes .dmx directly, the critic system is not needed — the 8 static validators in the Lark parser catch errors at parse time. For legacy markdown specs, the critic system validates the LLM's IR output.
THE THREE AGENTS
LLM-A
Generator / Repair Agent
Generates .dmx spec from natural language, repairs issues identified by critic
  • Converts markdown spec → SpecDraft (ApplicationIR)
  • Applies PATH-LOCKED patches
  • Repairs are MONOTONIC
  • Temperature = 0
LLM-B
Spec Critic Agent
Evaluates IR against Spec Quality Contract
  • Evaluates against 12 validation rules
  • Produces closure_score, blocking issues, patches
  • IR extraction: 180k → 15k tokens
  • NO repair authority
LLM-C
Triangulation Verifier
Validates that the critic (LLM-B) evaluated correctly
  • Runs deterministic checks FIRST (<10ms)
  • If contradiction → auto-disagree
  • Verdict: AGREE / DISAGREE / UNCERTAIN
  • NO AUTHORITY
  • Reduces tokens ~70%
THE CLOSURE LOOP
1
LLM-A generates .dmx draft
The LLM receives a natural language description and produces a .dmx spec draft. This is the authoring phase — before the Lark parser runs.
2
LLM-B critiques against quality contract
Evaluates 12 validation rules. Produces closure_score, blocking issues, and required patches.
3
Check Convergence
● Score ≥ 95% + no blocking → CONVERGED
● Plateau (unchanged 2 iters) → STOP
● Max iterations (3) reached → STOP
● Blocking issues remain → CONTINUE
4
LLM-A repairs (path-locked, monotonic)
Only modifies JSONPaths specified in required_patches. Constrained repair scope.
5
Monotonic Check — did score improve?
● YES → Continue to Step 6
● NO → Rollback to best IR, STOP
6
LLM-C Triangulation (optional)
● AGREE → Loop back to Step 2
● DISAGREE → STOP, escalate
● UNCERTAIN → Pass with warning
Loop back to Step 2 — Max 3 iterations

AUTO-DISAGREE (no LLM needed)
If any check fails + critic said is_closed=true → deterministic override, skip LLM-C call entirely. Runs in <10ms.
KEY PRINCIPLES
1
Deterministic Evaluation

temperature=0, same IR → same output

2
Path Locking

Repairs can only modify specified JSONPaths

3
Monotonic Closure

Score can only improve; worse → rollback

4
No Authority for LLM-C

Verifier only checks, never decides

5
Fail-Closed

Uncertain with low confidence → escalate to human

6
Evidence-First

All decisions backed by auditable evidence

7
Crash Safety

Append-only journal with fsync for crash recovery
